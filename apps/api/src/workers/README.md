Phase 3 runs a fixed pool of logical worker loops in the API process. Phase 4 extends those loops to claim pending rows and due `retry_wait` rows, apply typed error classification, and persist bounded retry timing. Phase 5 adds the expired-lease watchdog, terminal lifecycle detection, and systemic provider-failure cutoff. Every claim uses a short PostgreSQL transaction; all locks are released before limiter waits or simulator calls.

The coordinator starts after database readiness, detects an existing active job, and receives a non-blocking notification after each new upload commits. The limiter is process-wide and spaces every initial or retry start by 220 ms. When only future retries remain, one coordinator timer wakes at the earliest database-derived delay; workers do not sleep through backoff. Independent 8-second deadlines release worker capacity even if a transport ignores abort.

The watchdog scans with database time every `LEASE_REAPER_INTERVAL_MS`. It conditionally revokes one expired lease per short transaction and either schedules a new token-bearing attempt or records final exhaustion. Accepted provider failures increment the persisted job streak under the job lock, accepted success resets it, and stale callbacks change neither. At `SYSTEMIC_FAILURE_STREAK`, the same transaction fails the job, skips all unfinished rows, clears their leases, and preserves successful enrichments. Operational errors are logged and retried at the watchdog interval instead of abandoning a running job.
