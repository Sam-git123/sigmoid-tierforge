The coordinator runs a fixed pool of logical worker loops in each API process. Those loops claim pending rows and due `retry_wait` rows fairly across active jobs, apply typed error classification, and persist bounded retry timing. The expired-lease watchdog, terminal lifecycle detection, and systemic provider-failure cutoff remain job-scoped. Every claim uses a short PostgreSQL transaction; all locks are released before limiter waits or simulator calls.

The coordinator starts after database readiness, discovers every queued/running job, and receives a non-blocking notification after each local upload commits. One global retry timer wakes at the earliest database-derived due time; bounded periodic discovery lets another process observe new jobs. The PostgreSQL limiter spaces every initial or retry reservation by 220 ms across all processes. Independent request deadlines release worker capacity even if a transport ignores abort.

The watchdog scans with database time every `LEASE_REAPER_INTERVAL_MS`. It conditionally revokes one expired lease per short transaction and either schedules a new token-bearing attempt or records final exhaustion. Accepted provider failures increment the persisted job streak under the job lock, accepted success resets it, and stale callbacks change neither. At `SYSTEMIC_FAILURE_STREAK`, the same transaction fails the job, skips all unfinished rows, clears their leases, and preserves successful enrichments. Operational errors are logged and retried at the watchdog interval instead of abandoning a running job.
