Phase 3 runs a fixed pool of logical worker loops in the API process. Phase 4 extends those loops to claim pending rows and due `retry_wait` rows, apply typed error classification, and persist bounded retry timing. Every claim uses a short PostgreSQL transaction; all locks are released before limiter waits or simulator calls.

The coordinator starts after database readiness, detects an existing active job, and receives a non-blocking notification after each new upload commits. The limiter is process-wide and spaces every initial or retry start by 220 ms. When only future retries remain, one coordinator timer wakes at the earliest database-derived delay; workers do not sleep through backoff. Independent 8-second deadlines release worker capacity even if a transport ignores abort. General lease reaping, systemic-run termination, and restart recovery remain deferred.
